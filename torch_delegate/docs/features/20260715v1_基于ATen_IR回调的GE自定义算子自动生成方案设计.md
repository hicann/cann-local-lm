# 简介

## 目的

本文档描述了基于 ATen IR 回调的 GE 自定义算子自动生成方案的设计需求和实现细节。目标读者为 GE 图引擎开发人员、torchair 适配层开发人员以及自定义算子接入用户。

本方案旨在解决用户通过 PyTorch 自定义算子机制接入 GE 时需要重复编写交付件的问题，通过代码自动生成和 Dispatcher 回调机制，实现计算逻辑的自动复用。

## 范围

本文档涵盖以下内容：
- 方案背景和目标
- 三阶段设计流程（原型映射、Converter构图、Execute执行）
- 输入输出映射规则、值依赖注册、Schema元信息属性
- 用户接入规范和约束
- 框架实施优先级

本文档不包括以下内容：
- CPU 自定义算子的支持方案（本方案仅面向 NPU device 场景）
- libtorch Dispatcher 内部实现细节
- ATen IR 到 GE IR 的完整转换规则（仅覆盖通过回调复用的部分）

# 总体概述

## 软件概述

### 项目介绍

本项目是 GE 图引擎的一个新特性，用于简化用户自定义算子接入 GE 的流程。以往用户需要：
1. 实现 converter（完成 ATen IR → GE IR 的转换）
2. 实现入 GE 图的交付件（通过 `custom_op.h` 中的接口实现 `Execute` 函数）

本方案通过自动代码生成和 Dispatcher 回调，消除交付件的重复编写工作。

### 产品环境介绍

本产品是 GE 图引擎与 torchair 适配层协同工作的组件，在以下环境中运行：

**系统架构：**
```
PyTorch (TORCH_LIBRARY 注册) → libtorch Dispatcher → ATen IR
                                           ↓
torchair (FX Graph追踪) → GE Converter → GE ComputeGraph
                                           ↓
GE Runtime (Execute) → Dispatcher回调 → PrivateUse1 实现 → NPU算子执行
```

**外部接口：**
1. PyTorch TORCH_LIBRARY/TORCH_LIBRARY_IMPL：用户通过此接口注册自定义算子
2. torchair converter：遍历 FX Graph 构建 GE 节点
3. libtorch Dispatcher：GE Execute 通过此接口回调 ATen IR

**相关产品：**
- libtorch：PyTorch C++ 前端，提供 Dispatcher 机制
- torchair：PyTorch 到 GE 的适配层，负责图追踪和转换
- GE Runtime：图执行引擎，本方案主要涉及 runtime/v2 路径

## 竞品分析

### 对比维度

主流深度学习框架自定义算子机制对比：

| 维度 | TensorRT | PyTorch | JAX | Inductor | TensorFlow | **GE 本方案** |
|------|----------|---------|-----|----------|------------|---------------|
| **核心 API** | IPluginV3 | TORCH_LIBRARY | custom_ops | custom_op | REGISTER_OP | **REG_OP + Dispatcher** |
| **注册机制** | Plugin Registry | Dispatcher | JIT 装接 | Inductor 后端 | Kernel Registry | **Operator Factory** |
| **Schema 定义** | C++ 接口描述 | Python def 字符串 | Python 函数签名 | Python 函数签名 | C++ OP_DEF | **ATen schema 解析** |
| **Shape 推导** | getOutputDimensions | Meta key | 抽象评估 | Symbolic tracing | ShapeFn | **Meta key（复用 PyTorch）** |
| **执行模式** | Device Sink | Host Dispatch | XLA JIT | AOT 编译 | TFRT/CPU | **Dispatcher 回调** |
| **序列化** | serialize/deserialize | 无 | 无 | 无 | Bundle 打包 | **OM 文件（已有）** |
| **版本兼容** | Plugin Version | 无约束 | 无约束 | 无约束 | OpVersion | **待增强** |
| **主要语言** | C++ | Python/C++ | Python | Python | C++ | **C++ + Python（torchair）** |
| **适用场景** | 推理优化 | 训练+推理 | 科学计算 | PyTorch 2.x | 生产部署 | **在线推理（torchair）** |

### 借鉴点分析

本方案的设计借鉴了以下竞品的优秀设计：

| 设计决策 | 参考竞品 | 借鉴原因 |
|----------|----------|----------|
| **Meta Key 强制要求** | PyTorch | PyTorch 强制要求 Meta 实现，保证编译期 shape 推导正确性。GE 方案沿用此设计，确保静态 shape 场景不发生写越界。 |
| **Dispatcher 多后端路由** | PyTorch | PyTorch Dispatcher 可路由到不同后端（CPU/CUDA/PrivateUse1）。GE 借鉴 PrivateUse1 key 设计，实现 NPU 后端适配。 |
| **Schema 字符串定义** | PyTorch、JAX | Schema-driven 设计简洁易维护。GE CodeGen 解析 ATen schema 自动生成 REG_OP，消除手动维护负担。 |
| **序列化机制** | TensorRT | TensorRT 的 serialize/deserialize 支持引擎持久化。GE 已有 OM 文件序列化机制，应进一步增强算子版本兼容。 |
| **OP_DEF + Kernel 分离** | TensorFlow | TensorFlow 的 schema 定义与 Kernel 实现分离。GE REG_OP + IMPL_OP 设计类似，便于算子原型与实现独立演化。 |

### 差异点分析

本方案与竞品的关键差异：

| 维度 | GE 方案 | 竞品方案 | 差异原因 |
|------|----------|----------|----------|
| **适用场景** | 仅在线场景（torchair） | TensorRT：离线推理；PyTorch：训练+推理 | GE 动态 shape 场景依赖 Dispatcher 回调，离线编译（atc）不支持运行时注册 |
| **执行模式** | Dispatcher 回调（Host） | TensorRT：Task Sink（Device） | Dispatcher 回调灵活支持动态 shape，但引入 Host 调度开销；静态 shape 场景应保留 Sink 模式 |
| **序列化支持** | OM 文件序列化算子原型 | TensorRT：完整序列化（含版本）；PyTorch：无序列化 | GE OM 文件需增强算子版本兼容机制，参考 TensorRT Plugin Version |
| **算子打包** | so_in_om（部分支持） | TensorFlow：完整 Bundle 打包 | GE 应增强算子 Bundle 打包能力，支持算子依赖随模型分发 |
| **Meta 验证** | 手动验证 | PyTorch：torch.compile 自动验证 | GE 应提供 Meta 实现验证工具，降低用户负担 |

### 设计权衡说明

基于竞品分析，本方案的设计权衡：

1. **性能 vs 易用性**：选择易用性优先（Schema-driven + Dispatcher），牺牲部分性能（Host 调度开销），适用于在线场景
2. **灵活性 vs 约束**：选择约束优先（强制 Meta key），保证静态 shape 场景正确性
3. **编译期 vs 运行时**：选择运行时注册（依赖 PyTorch Dispatcher），适用于在线场景；离线场景待后续支持

## 软件功能

本方案提供以下核心功能：

1. **原型自动生成**：CodeGen 根据 ATen schema 自动生成 GE 算子原型（REG_OP）并注册到 operator factory
2. **Converter 自动构图**：torchair converter 遍历 FX Graph，自动构建 GE 节点并将 schema 信息编码为节点属性
3. **Execute 自动执行**：GE 内置通用 Execute 实现，通过读取节点属性动态构建 Dispatcher 调用

功能关系图：

```
ATen Schema → [CodeGen] → REG_OP + 值依赖注册 + 元信息属性
                                    ↓
FX Graph → [Converter] → GE Graph（Const节点、合并算子）
                                    ↓
GE Execute → [BuildStack] → Dispatcher调用 → [WriteBack] → GE输出Tensor
```

## 设计约束

### 用户必须提供的约束

1. **Schema 定义**：通过 `TORCH_LIBRARY` 注册完整 schema，数据类型只使用 GE 与 PyTorch 共同支持的类型
2. **Meta key 实现**：必须注册 Meta key，供 torchair 编译阶段符号形状推导
3. **PrivateUse1 key 实现**：必须注册 PrivateUse1 key 的计算实现，供 GE Execute 通过 Dispatcher 回调
4. **so 加载顺序**：`libcust_opapi.so` 必须在进入 GE 执行前加载

### 框架自动完成的约束

1. **Schema 驱动**：所有代码生成基于 schema 分析，而非硬编码
2. **零拷贝优先**：NPU 场景下优先使用零拷贝方案
3. **统一承载模型**：所有非 Tensor 参数统一转为 Tensor 输入边，消除路径分裂

### 不支持的场景

- 含 `Device` / `Layout` / `Generator` / `MemoryFormat` 参数的 schema
- 含 `complex` 类型 Scalar 默认值（P0 不支持）
- 含 `Tensor[]` 但无法静态确定输出数量上界
- schema 解析失败的情况

## 假设和依赖关系

### 本迭代的依赖

1. **libtorch Dispatcher**：依赖 Dispatcher 机制查找和调用 ATen IR
2. **torchair converter**：依赖 torchair 提供 FX Graph 追踪和节点构建能力
3. **GE operator factory**：依赖 GE 提供算子注册机制（REG_OP/IMPL_OP）
4. **GE runtime/v2**：依赖 GE runtime v2 提供 Execute 执行环境

### 假设

1. 用户已正确注册 TORCH_LIBRARY 和 TORCH_LIBRARY_IMPL
2. Meta key 实现的形状推导正确
3. PrivateUse1 key 实现的计算逻辑正确
4. `libcust_opapi.so` 在运行时已加载

# 特性需求分析&设计

## 整体介绍

本方案通过三阶段设计实现自定义算子的自动接入：

| 阶段 | 职责 | 输入 | 输出 |
|------|------|------|------|
| **步骤一：原型映射** | CodeGen 根据 schema 生成 REG_OP | ATen schema | REG_OP + 值依赖注册 + 元信息属性 |
| **步骤二：Converter 构图** | 遍历 FX Graph 构建 GE 节点 | FX Graph + schema | GE Graph（含 Const 节点、合并算子） |
| **步骤三：Execute 执行** | 从 gert::Tensor 转 torch API 调用 | GE 输入 + 元信息属性 | Dispatcher 调用 + WriteBack |

流程图：
```
[构建/加载阶段] CodeGen 扫描 TORCH_LIBRARY 注册的 ATen schema
                自动生成 REG_OP 代码并注册到 GE operator factory
                注册值依赖（InputsDataDependency）
                保存 schema 元信息为节点属性
    ↓
[图追踪阶段] torchair 遍历 FX Graph，对每个 call_function 节点调用 converter
    ↓
converter 处理参数：
  - Tensor 参数：直接连上游输出边
  - 非 Tensor 常量：创建 Const 节点（HOST 内存）
  - 非 Tensor 动态值：连上游算子输出边
  - 列表参数：生成合并算子
  - Optional None：可选输入不连边
    ↓
converter 在 GE 图中创建节点，写入元信息属性
    ↓
[运行时] GE Execute 被调用：
  1. 根据 input_kinds 判断每个参数类型
  2. 从输入边取值（Tensor 包装 / 标量提取）
  3. 通过 Dispatcher 调用 ATen IR（PrivateUse1 key）
  4. 将结果写回 GE 输出 Tensor
```

## 功能需求

### 功能需求1：原型映射规则（REG_OP 生成）

#### 1. 介绍

CodeGen 根据 ATen schema 自动生成 GE 算子原型，包括输入输出映射、值依赖注册、Schema元信息属性等。这是用户无需手动编写交付件的核心机制。

#### 2. 输入

- **来源**：用户通过 TORCH_LIBRARY 注册的 ATen schema
- **数量**：根据用户注册的算子数量决定
- **度量单位**：schema 条目
- **有效输入范围**：GE 与 PyTorch 共同支持的 ATen schema（排除 Device/Layout/Generator/MemoryFormat 参数）
- **时间要求**：构建阶段一次性生成

#### 3. 处理

**算子标识符与命名：**
- schema 名 `my_ops::my_op` → REG_OP 标识符 `my_ops__my_op`（`::` → `__`）
- schema 名 `my_ops::add.Tensor` → REG_OP 标识符 `my_ops__add_Tensor`（`.` → `_`）
- GE 图中节点类型字符串仍保留 schema 名以保证 dump 可读性

**输入参数映射规则：**

核心设计：所有非 Tensor 参数 → Tensor 输入边

| Schema 参数 | REG_OP 声明 | 值依赖 | dtype 约束 |
|------------|------------|--------|-----------|
| `Tensor name` | `.INPUT(name, TensorType::ALL())` | 否 | 无约束 |
| `Tensor? name=None` | `.OPTIONAL_INPUT(name, TensorType::ALL())` | 否 | 无约束 |
| `Tensor[] name` | `.DYNAMIC_INPUT(name, TensorType::ALL())` | 否 | 无约束 |
| `int name`（无默认值）| `.REQUIRED_INPUT(name, IntTensorType())` | **是** | int64 |
| `int name=v`（有默认值）| `.OPTIONAL_INPUT(name, IntTensorType())` | **是** | int64 |
| `float name` | `.REQUIRED_INPUT/OPTIONAL_INPUT(name, FloatTensorType())` | **是** | float32 |
| `bool name` | `.REQUIRED_INPUT/OPTIONAL_INPUT(name, BoolTensorType())` | **是** | bool |
| `Scalar name` | `.REQUIRED_INPUT/OPTIONAL_INPUT(name, TensorType::ALL())` | **是** | 多态（由 tensor dtype 表达） |
| `int[] name` | `.REQUIRED_INPUT/OPTIONAL_INPUT(name, IntTensorType())` | **是** | 1-dim int tensor |
| `str name` | `.REQUIRED_INPUT/OPTIONAL_INPUT(name, StringTensorType())` | **是** | string |
| `ScalarType name` | `.REQUIRED_INPUT/OPTIONAL_INPUT(name, IntTensorType())` | **是** | int64（枚举值） |

**必选/可选判断规则：**
- 无默认值的非 Optional 参数 → `.REQUIRED_INPUT`
- 有默认值或 Optional 参数 → `.OPTIONAL_INPUT`

**值依赖注册：**

非 Tensor 参数（除 `Tensor`、`Tensor?`、`Tensor[]` 外）都需要注册为值依赖：

```cpp
// REG_OP 示例
REG_OP(my_ops__my_op)
    .INPUT(x, TensorType::ALL())
    .REQUIRED_INPUT(dim, IntTensorType())           // int → 值依赖
    .OPTIONAL_INPUT(alpha, TensorType::ALL())       // Scalar → 值依赖
    .OUTPUT(y, TensorType::ALL())
    .OP_END_FACTORY_REG(my_ops__my_op)

// IMPL_OP 中注册值依赖
IMPL_OP(my_ops__my_op)
    .InputsDataDependency({"dim", "alpha"})         // 非 Tensor 参数名列表
```

**Schema 元信息属性：**

保留 schema 元信息为节点属性，供 Execute 使用：

```cpp
REG_OP(my_ops__my_op)
    // ... 输入输出声明 ...

    // Schema 元信息属性
    .ATTR(op_name, String, "my_ops::my_op")         // Dispatcher 查找
    .ATTR(input_kinds, ListInt, {...})              // 每个参数的类型编码
    .ATTR(num_outputs, Int, 1)                      // 输出数量
    .ATTR(is_inplace, Bool, false)                  // inplace 标记
    .OP_END_FACTORY_REG(my_ops__my_op)
```

| 属性 | 类型 | 用途 | 来源 |
|------|------|------|------|
| `op_name` | String | Dispatcher 查找 OperatorHandle | schema 名 |
| `input_kinds` | ListInt | 每个参数的 InputKind 编码 | schema 参数类型 |
| `num_outputs` | Int | WriteBack 循环边界 | schema 输出数 |
| `is_inplace` | Bool | WriteBack 模式选择 | schema inplace 标注 |

**InputKind 编码定义：**

```cpp
enum InputKind {
    // Tensor 类（不走值依赖）
    TENSOR = 0,
    OPTIONAL_TENSOR = 1,
    TENSOR_LIST = 2,

    // 标量类（走值依赖）
    INT = 10,
    INT_OPT = 11,
    FLOAT = 12,
    FLOAT_OPT = 13,
    BOOL = 14,
    BOOL_OPT = 15,
    SCALAR = 16,
    SCALAR_OPT = 17,

    // 列表类（走值依赖）
    INT_LIST = 20,
    INT_LIST_OPT = 21,
    FLOAT_LIST = 22,
    BOOL_LIST = 23,

    // 特殊类（走值依赖）
    STRING = 30,
    STRING_OPT = 31,
    SCALAR_TYPE = 32,
    SCALAR_TYPE_OPT = 33,
};
```

**异常情况处理：**
- schema 解析失败：跳过 REG_OP 生成，converter 在运行时触发 fallback
- 不支持的参数类型：跳过生成

#### 4. 输出

- **输出到何处**：GE operator factory（通过 REG_OP 注册）
- **数量**：一个算子对应一个 REG_OP
- **度量单位**：算子原型
- **时序**：构建阶段一次性生成
- **有效输出范围**：符合 GE 算子注册规范的原型

### 功能需求2：Converter 构图转换

#### 1. 介绍

torchair converter 遍历 FX Graph，对每个自定义算子节点构建对应的 GE 节点，处理参数映射并写入元信息属性。

#### 2. 输入

- **来源**：torchair FX Graph（call_function 节点）
- **数量**：根据 FX Graph 中自定义算子的数量决定
- **度量单位**：FX Node
- **有效输入范围**：已注册 schema 的自定义算子节点
- **时间要求**：图追踪阶段实时构建

#### 3. 处理

**参数处理规则：**

| FX args 形态 | Converter 行为 | GE 图结构 |
|-------------|---------------|----------|
| Tensor（FX Node）| 直接连上游输出边 | 输入边连接上游节点 |
| 常量字面量 | 创建 Const 节点 | Const 节点（HOST 内存）连边 |
| FX Node（0-dim tensor）| 直接连上游输出边 | 输入边连接上游节点 |
| FX Node（SymInt 输出，如 `aten.size`）| 连上游输出边 | 输入边连接 `aten.size` 等节点 |
| 列表参数（`int[]`）| 生成合并算子 | 合并算子输出连边 |
| None（Optional）| 不连边 | OPTIONAL_INPUT 缺边 |
| 缺省（使用默认值）| 创建 Const 节点存默认值 | Const 节点连边 |

**Const 节点创建：**

```python
def create_const_node(value, input_kind):
    # 根据 input_kind 选择 dtype
    dtype_map = {
        INT: "int64",
        INT_OPT: "int64",
        FLOAT: "float32",
        FLOAT_OPT: "float32",
        BOOL: "bool",
        BOOL_OPT: "bool",
        SCALAR: infer_dtype_from_value(value),  # Python 类型推断
        STRING: "string",
        SCALAR_TYPE: "int64",  # 枚举值
    }

    dtype = dtype_map[input_kind]
    const_node = CreateConstNode(value, dtype, placement=HOST)
    return const_node
```

**Const 节点特性：**
- value tensor 存储在 HOST 内存
- dtype 按 schema 类型或 Python 字面量类型选择
- Execute 读取零开销（无 D2H 同步）

**列表参数处理：**

```python
def process_list_arg(args_list, input_kind):
    tensors = []
    for arg in args_list:
        if is_literal(arg):
            # 常量：创建 Const 节点
            tensors.append(create_const_node(arg, input_kind))
        elif is_fx_node(arg):
            # 上游节点：直接引用
            tensors.append(arg)

    # TODO: 生成合并算子，将多个 tensor 合为单个 tensor
    merge_node = CreateMergeOp(tensors, dtype=get_dtype(input_kind))
    return merge_node.output
```

**异常情况处理：**
- 合并算子尚未实现（P0 TODO）：当前跳过列表参数处理
- 不支持的参数类型：运行时 fallback

#### 4. 输出

- **输出到何处**：GE ComputeGraph（节点）
- **数量**：一个 FX Node 对应一个 GE Node
- **度量单位**：GE Node
- **时序**：图追踪阶段实时构建
- **有效输出范围**：符合 GE 图规范的节点

### 功能需求3：Execute 执行转换

#### 1. 介绍

GE Execute 函数通过读取节点属性，动态构建 Dispatcher 调用栈，回调 ATen IR 实现计算逻辑，并将结果写回 GE 输出 Tensor。

#### 2. 输入

- **来源**：GE runtime v2 执行环境
- **数量**：每次执行一次调用
- **度量单位**：Execute 函数调用
- **有效输入范围**：gert::Tensor 输入（NPU device HBM 内存）
- **时间要求**：运行时实时执行

#### 3. 处理

**整体流程：**

```cpp
graphStatus Execute(gert::EagerOpExecutionContext* ctx) {
    // 1. 获取元信息
    auto op_name = ctx->GetAttr<std::string>("op_name");
    auto input_kinds = ctx->GetAttr<std::vector<int>>("input_kinds");
    auto is_inplace = ctx->GetAttr<bool>("is_inplace");
    auto num_outputs = ctx->GetAttr<int>("num_outputs");

    // 2. 构建调用栈
    c10::Stack stack = BuildStack(ctx, input_kinds);

    // 3. Dispatcher 调用
    static auto& op_handle = GetCachedHandle(op_name);
    op_handle.callBoxed(&stack);

    // 4. WriteBack
    WriteBack(ctx, stack, is_inplace, num_outputs);

    return GRAPH_SUCCESS;
}
```

**BuildStack 实现：**

```cpp
c10::Stack BuildStack(gert::EagerOpExecutionContext* ctx,
                      const std::vector<int>& input_kinds) {
    c10::Stack stack;
    int input_idx = 0;

    for (int kind : input_kinds) {
        auto* tensor = ctx->GetInputTensor(input_idx);

        // Optional 缺边处理
        if (tensor == nullptr) {
            if (IsOptional(kind)) {
                stack.emplace_back(c10::nullopt);
            } else {
                GELOGE("Required input %d is missing", input_idx);
                throw std::runtime_error("Required input missing");
            }
            input_idx++;
            continue;
        }

        // 根据类型提取值
        switch (kind) {
            case TENSOR:
            case OPTIONAL_TENSOR:
                stack.emplace_back(WrapNpuTensor(tensor));
                break;

            case INT:
            case INT_OPT:
                stack.emplace_back(ExtractInt(tensor));
                break;

            case FLOAT:
            case FLOAT_OPT:
                stack.emplace_back(ExtractFloat(tensor));
                break;

            case BOOL:
            case BOOL_OPT:
                stack.emplace_back(ExtractBool(tensor));
                break;

            case SCALAR:
            case SCALAR_OPT:
                stack.emplace_back(ExtractScalar(tensor));
                break;

            case INT_LIST:
            case INT_LIST_OPT:
                stack.emplace_back(ExtractIntList(tensor));
                break;

            // ... 其他类型处理
        }

        input_idx++;
    }

    return stack;
}
```

**Tensor 包装：**

```cpp
at::Tensor WrapNpuTensor(const gert::Tensor* ge_tensor) {
    auto sizes = GetShape(ge_tensor->GetStorageShape());
    auto dtype = MapGeDtypeToTorch(ge_tensor->GetDataType());
    int32_t device_id = GetCurrentDeviceId();

    return torch::from_blob(
        const_cast<void*>(ge_tensor->GetAddr()),
        sizes,
        [](void*) {},  // GE 管理内存，torch 不负责释放
        torch::TensorOptions()
            .dtype(dtype)
            .device(c10::Device(c10::DeviceType::PrivateUse1, device_id))
    );
}
```

**WriteBack 实现：**

```cpp
void WriteBack(gert::EagerOpExecutionContext* ctx, c10::Stack& stack,
               bool is_inplace, int num_outputs) {
    for (int i = 0; i < num_outputs; ++i) {
        at::Tensor result = stack[i].toTensor();
        if (!result.is_contiguous()) {
            result = result.contiguous();
        }

        if (is_inplace && i == 0) {
            // inplace：结果写回输入 0
            const gert::Tensor* input_0 = ctx->GetInputTensor(0);
            aclrtMemcpy(const_cast<void*>(input_0->GetAddr()),
                        input_0->GetSize(),
                        result.data_ptr(), result.nbytes(),
                        ACL_MEMCPY_DEVICE_TO_DEVICE);
            ctx->MakeOutputRefInput(0, i);
        } else {
            // 非 inplace：分配输出并写入
            ge::DataType ge_dtype = MapTorchDtypeToGe(result.scalar_type());
            gert::Tensor* ge_out = ctx->MallocOutputTensor(
                i, result.sizes(), ge::FORMAT_ND, ge_dtype);
            aclrtMemcpy(ge_out->GetAddr(), ge_out->GetSize(),
                        result.data_ptr(), result.nbytes(),
                        ACL_MEMCPY_DEVICE_TO_DEVICE);
        }
    }
}
```

| 在线场景（框架适配） | **适用** | 方案主要面向 torchair 框架适配，通过 converter 遍历 FX Graph 构建 GE 节点，通过 Execute 回调 ATen IR。这是典型的在线场景。 |

## 性能

### 模型编译时长

本特性涉及以下编译阶段：

1. **CodeGen（原型映射）**：扫描 TORCH_LIBRARY 注册的 ATen schema，生成 REG_OP。新增代码影响较小，主要是 schema 解析和代码生成，编译时长增加可控（预计 <1s）。

2. **torchair converter（构图）**：遍历 FX Graph 构建 GE 节点。新增代码为参数处理逻辑，对编译时长影响较小。

**影响评估：** 编译时长影响可控，不影响 optimizeStage1、optimizeStage2、build、loadmodelonline 等关键阶段。

### OM 大小和加载占用内存

本特性仅适用于在线场景，不涉及 OM 文件生成。加载时无额外内存占用。

### 执行性能

**关键执行路径：**
1. BuildStack：构建调用栈，涉及遍历 input_kinds 和值提取
2. Dispatcher 调用：通过 `op_handle.callBoxed` 调用 ATen IR
3. WriteBack：结果写回，涉及 `aclrtMemcpy`

**性能影响评估：**
- BuildStack：每次执行遍历 input_kinds，预计耗时 <100ns（小图）
- Dispatcher 调用：依赖 libtorch Dispatcher 实现，预计耗时 <1us
- WriteBack：涉及 D2D 拷贝，耗时取决于输出 tensor 大小

**性能优化建议：**
1. OpCache：缓存 `op_handle` 避免重复查找（P2）
2. 避免 BuildStack 中的动态内存申请（按 RT2 约束）
3. 标量参数使用编译时常量类型（按用户接入规范）

## 附录 B：用户自定义算子接入规范

### B.1 功能正确性约束（必须满足）

**1. Schema 定义**
通过 `TORCH_LIBRARY` 注册完整 schema，数据类型只使用 GE 与 PyTorch 共同支持的类型。Inplace 语义用 `Tensor(a!)` 显式标注；多输出在 `->` 后显式列出所有输出。

**2. Meta key 实现（必须）**
必须注册 Meta key，torchair FX 图追踪阶段依赖 Meta tensor 做符号形状推导，缺失直接导致入图失败。Meta 实现必须**正确推导输出的 shape 和 dtype**，形状推导错误会导致静态 shape 场景下 Execute 写越界。Meta 实现只做纯形状推导，不调用任何 NPU/设备接口。

```cpp
TORCH_LIBRARY_IMPL(my_ops, Meta, m) {
    m.impl("my_op", [](const at::Tensor& x, const at::Tensor& y) {
        // 正确推导输出 shape 和 dtype，不做实际计算
        return at::empty(compute_output_shape(x, y),
                         x.options().dtype(compute_output_dtype(x, y)));
    });
}
```

**3. PrivateUse1 key 实现（必须）**
必须注册 PrivateUse1 key 的计算实现，GE Execute 通过 Dispatcher 命中此 key；若仅注册 Meta，运行时 dispatch 失败返回 `GRAPH_FAILED`。算子实现使用 `getCurrentNPUStream()` 获取当前 stream；GE Execute 在调用 Dispatcher 前已将 GE stream 桥接为当前 NPU stream，算子无需额外处理。

**4. so 加载顺序**
`libcust_opapi.so` 必须在进入 GE 执行前加载（`torch.ops.load_library` 或 `dlopen`）；未加载时 `findSchemaOrThrow` 直接抛异常。

### B.2 性能最佳推荐做法

**5. 标量参数使用编译时常量类型**
`alpha`、`dim`、`keepdim`、`scale` 等标量参数在 schema 中定义为 `float/int/bool` 类型，不要定义为 `Tensor`。`torch.compile` 追踪时会将其固化为常量，走 Const 节点 HOST 内存路径，Execute 零开销读取。

```cpp
// 推荐：标量参数直接定义为 float
m.def("my_op(Tensor x, Tensor y, float alpha=1.0) -> Tensor");

// 不推荐：标量用 Tensor 传递
m.def("my_op(Tensor x, Tensor y, Tensor alpha) -> Tensor");
```

**6. 算子实现直接返回连续 tensor**
PrivateUse1 实现中，输出 tensor 应为连续内存布局（contiguous）。非连续 tensor 会在 WriteBack 时触发额外 `contiguous()` 拷贝。

**7. 输出使用 ND 格式**
算子输出使用标准多维数组格式（ND）。非 ND 格式不在本方案支持范围内。

### B.3 约束汇总

| 项目 | 类别 | 违反后果 |
|------|------|---------|
| 注册 schema，数据类型在 GE/PyTorch 共同支持范围内 | 功能必须 | 不支持类型回退到手动实现路径 |
| Inplace 用 `Tensor(a!)` 显式标注 | 功能必须 | inplace 语义识别错误，内存管理异常 |
| Meta key 实现，且形状推导正确 | 功能必须 | 缺失：FX 图追踪失败；形状错误：Execute 写越界 |
| PrivateUse1 key 实现 | 功能必须 | 运行时 dispatch 失败，返回 `GRAPH_FAILED` |
| so 在 GE 执行前加载 | 功能必须 | `findSchemaOrThrow` 抛异常 |
| 标量参数用 `float/int/bool`，不用 `Tensor` | 性能推荐 | 每次 Execute 引入 D2H 同步，打断 NPU 流水线 |
| 算子实现返回连续 tensor | 性能推荐 | WriteBack 触发额外 `contiguous()` 拷贝 |
| 输出使用 ND 格式 | 性能推荐 | 不在本方案支持范围，需格式转换 |
