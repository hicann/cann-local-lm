# Artifact Protocol

The field-level reference schema is located at
[`examples/manifest_schema/manifest-v1.schema.json`](../examples/manifest_schema/manifest-v1.schema.json).
That file is the v1 protocol reference and does not participate in build or runtime validation. The Python field definitions are located in
`python/executorch_npu/artifacts/manifest.py`, managed by Pydantic models.
The artifact construction layer checks the corresponding business conditions during graph mapping, weight registration, and multi-method state aggregation;
artifacts written to disk are parsed and validated by `runtime/manifest.cpp`.

`compiler.compile_partition()` returns the OM and weight file paths. Before the temporary directory is released, the backend calls
`artifacts.builder.build_manifest()` to construct the `Manifest` and register named data.
For multiple methods, after `check_manifest_set()` verifies the delegate backend identities and shared state,
`Manifest.to_bytes()` is called to generate JSON UTF-8 bytes with the ASCD header added, handed to
ExecuTorch to write into the PTE. The compilation flow no longer decodes the generated bytes, nor does it call a separate
`validate_manifest()`. The original `encode_manifest()` call is replaced by `manifest.to_bytes()`;
when diagnostics are needed, read the ASCD header first, then use JSON tools to inspect the payload content.

JSON fields and nesting remain unchanged from v1; optional fields are omitted when unset. The order of JSON keys is determined by the model
field declarations, so the output remains deterministic, but it is not required to be byte-identical to the old implementation.

The `processed_bytes` of each delegate backend uses the following format:

```text
ASCD | uint16_le framing_version=1 | uint32_le json_length | UTF-8 JSON
```

v1 protocol constraints:

- `runtime_protocol.version=1`, `artifact_abi=1`.
- `runtime_protocol.name=AscendBackend`.
- The OM is stored as named data inside the PTE; external weights are stored as PTD named data.
- Both the OM and weight groups record the full SHA-256 digest and logical byte length.
- `acl_soc_name` denotes both the GE compilation target and the ACL SoC name that must match exactly at runtime.
- A delegate backend is jointly identified by the method name and its serialized numeric index.
- The state field of stateless artifacts is fixed to `{"bindings":[]}`.

All weight lengths in the manifest are logical lengths. At runtime, device memory allocation and external weight binding use a fixed
32-byte alignment, and binding offsets must also be 32-byte aligned.

`ascend_name` stores the tensor name from the EPAIR or the `ExportedProgram`. After the CANN graph is built,
ACL descriptors may provide aliases for boundary tensors: inputs use `arg_<index>`, and outputs use
`output_<index>_<optimized-op>_<edge>`. When the runtime performs name validation, a tensor with the same index may
use either its original name or the CANN alias above; the tensor count, direction, index, data type, number of dimensions,
shape, and byte size must still match strictly.

For stateful delegate backends, each `state.bindings` entry maps one `state_current` input to one
`state_next` output; if the delegate backend does not update the state, `next_output_arg=-1` is used. At runtime,
`(device_id, state_namespace, state_id)` serves as the state key. `on_prefill` allows only one reset
owner; `explicit` can only be reset through the public state API; `device_only` state is never copied back to the host.
