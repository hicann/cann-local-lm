# ExecuTorch-NPU C++ Backend SDK Reference

This document describes the stable contents and interface boundaries of the C++ SDK inside the wheel. For the complete application compilation, PTE/PTD loading, and
device execution steps, see [Running in C++](runtime_en.md).

## Locating the SDK

After installing the wheel, obtain the SDK root directory through a lightweight API:

```bash
python -c "from executorch_npu import sdk_root; print(sdk_root())"
```

This operation does not require Torch and does not import the Python AOT Backend.

## SDK Contents in the Wheel

```text
executorch_npu/_sdk/
├── cmake/
│   ├── executorch_npu_backend.cmake
│   └── executorch_npu_executorch.cmake
├── include/executorch_npu/state.h
├── lib/
│   ├── libexecutorch_npu_manifest.a
│   └── libexecutorch_npu_backend.a
└── compatibility.json
```

The SDK does not include:

- The Runner executable.
- ExecuTorch, CANN Toolkit, drivers, firmware, or NNRT.
- PTE, PTD, model weights, or input data.
- Backend internal class declarations, implementation source, or test source.
- A direct invocation interface for `AscendBackend::init/execute/destroy`.

## CMake targets

Applications include:

```cmake
include("$ENV{EXECUTORCH_NPU_SDK}/cmake/executorch_npu_backend.cmake")
```

Public target:

```text
executorch_npu::backend
```

This target transitively provides:

- The Backend and Manifest static libraries.
- The Backend whole-archive registration requirement.
- ExecuTorch-NPU public headers.
- ExecuTorch 1.5 `executorch::runtime` or a CMake 3.24–3.27 compatible link path.
- OpenSSL Crypto and `libascendcl.so`.

The following targets are internal SDK implementation details and must not be linked directly by applications:

```text
executorch_npu_backend_archive
executorch_npu_manifest_archive
executorch_npu::executorch_runtime
```

## Backend Registration and Invocation Boundary

`libexecutorch_npu_backend.a` registers `AscendBackend` through static initialization. The registration
objects must be preserved at link time, so the SDK CMake interface uses whole-archive.

Call chain:

```text
User application
→ ExecuTorch Module API
→ ExecuTorch Runtime
→ PTE BackendDelegate.id = AscendBackend
→ AscendBackend init / execute / destroy
→ AscendCL
→ Ascend NPU
```

User applications only call the ExecuTorch Runtime or Module API; they do not call Backend lifecycle methods directly.

## Stateful API

```cpp
#include <executorch_npu/state.h>
```

Public interfaces:

```cpp
StateStatus SetStateInitializer(
    int device_id,
    const char* state_namespace,
    const char* state_id,
    const StateTensorData& initializer);

StateStatus ResetState(
    int device_id,
    const char* state_namespace,
    const char* state_id,
    const StateTensorData& source);

StateStatus ReleaseStateNamespace(
    int device_id,
    const char* state_namespace);
```

State is isolated by `(device_id, state_namespace, state_id)`. The Backend uses current/next
double buffering and commits the state swap only after successful execution. For the state protocol, see [Artifact Protocol](protocol_en.md).

## Compatibility metadata

`compatibility.json` is generated by the build process and records:

```text
ExecuTorch-NPU package version
Build type
Python version
ExecuTorch version and git commit
CANN version
C++ compiler version
```

The Backend static libraries and the ExecuTorch Runtime must remain compatible. Do not modify this file by hand, and do not
freely combine the `.a` files from one wheel with a different ExecuTorch version.

Models are delivered independently of the wheel:

```text
model.pte
ascend.weights.package.ge_aot.ptd
```

The execution machine must also provide the CANN Runtime, drivers, firmware, NNRT, the system C++ Runtime, and OpenSSL.

## Backend Secondary Development

The wheel SDK is for application integration and does not replace the ExecuTorch-NPU source development environment. When modifying the Backend, Manifest,
ACL execution, or state implementation, rebuild the wheel and static libraries from this repository's source. Ordinary applications no longer need
to compile ExecuTorch 1.5 source.
