## 一、一句话现状

我们做完了大模型推理流水线里**"挑下一个字"那一步**的零件（叫 Sampler，采样器），用 **C++** 写的，配了 **100 条自动测试、全部通过、零编译警告**。剩下两块（接真实昇腾硬件、加扩展功能）暂时做不了或没必要做，原因在第五节。

---

## 二、这到底是个什么东西（外行版）

大模型"生成文字"其实就是**一个字一个字往外蹦**。每蹦一个字之前，模型会给词表里**每个候选字打一个分**（这堆分叫 logits）。然后要决定"这次蹦哪个字"——**采样器就是干这个的**：拿这些分，按你给的几条规则，挑出一个字，并交出"我为什么挑它"的概率表。

打个比方：模型是出题老师，每步给全班（词表）每个学生打分；采样器是**按你定的"录取规则"决定录取哪个学生**的招生办。

它只管"挑哪个字"这一步。别的——算分（老师出题）、循环（一步一步蹦）、判停（蹦够了吗/说完了吗）、最后把数字翻回文字（解码）——都不归它，归别的模块。

## 四、怎么知道它是对的

- **测试先行**：先写"标准答案"（测试），再写"作业"（代码）。作业对上标准答案才算过——不会出现"写完一坨代码不知道对不对"。
- **100 条全绿**（0 失败），编译**零警告**（开了严格模式 `-Werror`）。
- 期望值用**独立的数学公式直接算**，不靠被测代码——避免"自己考自己"的盲区。
- 覆盖了边角情况：
  - 10 万词表不崩、概率和≈1；
  - 全 -∞ 输入能兜底（退化为均匀）不报错；
  - 重复惩罚对正分/负分两种公式都验；
  - 同样的输入 + 同一个随机种子 → 结果可复现；
  - 全旋钮齐开组合不出 nan/异常。

## 五、还没做 / 做不了的（诚实交代）

### ⛔ 接真实昇腾硬件——被阻塞
- 本机查过：装了 CANN 软件工具链，但 **`aclrtGetDeviceCount` 返回 0——没有可用的 NPU（昇腾）设备**。
- 所以"设备版"采样器没法在这台机器验证。硬写出来就是**没测过的代码**，我们一直守着"先测后算过"的纪律，不愿写未验证代码。
- **而且**：采样本身是在 CPU 上算的（挑字那一步很轻）。所以现在这版很可能**就是最终接口**——真正在设备上的数据搬运（device↔host）归别的模块管，不归采样器。
- 结论：等有设备、或确认需要"设备侧采样"再说。

### ⏸ 扩展功能——暂缓（没需求驱动前不做）
设计文档里原本留了三个扩展，都标了"按需/首版不做"，没有真实需求驱动前硬做是写一堆没人用的代码：
- 投机采样（小模型先猜、大模型验证的加速法）——标"预留，首版不做"。
- 批量 >1（一次处理多句话）——标"首版 batch=1"。
- 截断概率分布（省显存）——标"若显存吃紧才加"，目前没压力。

## 六、几个关键设计决定（为什么这么定）

1. **只做"采样"一步**，前后的活（前向/循环/判停/解码）明确划给别人——边界清晰、好测、不越界。
2. **C++ 风格**：采样器无状态（不记历史），所以对外是**静态方法**，不搞面向对象的"先 new 一个对象再调"。
3. **重复惩罚进了采样器**（用户明确要求），且**必须排在 Top-K/Top-P 前面**——否则被屏蔽的字会逃过惩罚（实测验证过这条顺序敏感性）。
4. **测试是设计真源**：SPEC/GUIDE/test 三处一致，改一处其它两处跟着改。

---

## 七、下一步建议

- **短期**：到此告一段落。采样器本身稳、测过、绿。
- **等外部就绪**：
  1. 有 NPU 设备时→做设备版（或确认 host 版即生产版）。
  2. 别人把 runner/backend（前后模块）做好后→做联调对接。
- **需求驱动时**：再做那三个扩展。
